# فرضيات تمريضية | Nursing Hypotheses

موقع ويب تعليمي تفاعلي ثنائي اللغة لتدريب التفكير السريري التمريضي عبر حالات خيالية متفرعة. يبدأ المحتوى بالإنجليزية، وتتوفر له ترجمة عربية وشرح للقرار والبدائل ومراجع يمكن الرجوع إليها. التصميم مستجيب للمتصفح، وليس تطبيق جوال أصلياً.

> **حد الاستخدام:** هذا الموقع للتعلم والمحاكاة فقط. لا يقدم تشخيصاً أو أمراً علاجياً، ولا يثبت الكفاءة المهنية، ولا يستبدل الحكم السريري أو سياسات المنشأة أو نطاق الممارسة. لا تُدخل أي بيانات مريض حقيقي.

## التشغيل المحلي | Local run

المتطلبات: إصدار حديث مدعوم من Node.js و`pnpm`. من جذر المشروع:

```powershell
pnpm install --frozen-lockfile
pnpm dev -- --port 4173 --strictPort
```

بعد ظهور عنوان Vite افتح:

- الصفحة الرئيسة: <http://localhost:4173/#/home>
- السيناريوهات: <http://localhost:4173/#/scenarios>
- بنك الأسئلة: <http://localhost:4173/#/questions>
- تقدّم التعلم: <http://localhost:4173/#/learning>
- المراجع: <http://localhost:4173/#/resources>

يوقف `--strictPort` التشغيل إذا كان المنفذ `4173` مستخدماً بدلاً من الانتقال بصمت إلى منفذ آخر.

## فحوص المشروع | Project checks

هذه هي الأوامر المقصودة للقالب؛ لا تعني كتابتها هنا أنها نجحت في جهاز أو نشر بعينه:

```powershell
pnpm test
pnpm build
pnpm test:sites
```

- `pnpm test`: يشغّل اختبارات Node الموجودة، ومنها قواعد الدرجات والتخزين والمزامنة وحدود Supabase الأمنية.
- `pnpm build`: يبني واجهة Vite ثم يجهز حزمة Sites.
- `pnpm test:sites`: يتحقق من سلوك عامل الاستضافة والمسارات الاحتياطية.
- عند نجاح بناء Sites فعلياً ينبغي أن توجد `dist/client/index.html` و`dist/server/index.js` و`dist/.openai/hosting.json`؛ يجب التحقق منها في ناتج التشغيل، لا افتراضها.

## ما يقدمه الموقع الآن | Current scope

- واجهة كاملة بالعربية والإنجليزية مع اتجاهي RTL/LTR.
- تصميم ويب سريري مستجيب مستوحى من مساحة قرار باللونين الكحلي والفيروزي، مع هدف عرض بعرض `390px` دون تمرير أفقي.
- 12 حالة خيالية أصلية في 12 مجالاً سريرياً، مع 24 تنويع عرض خاصاً بالحالة، و39 نقطة قرار، و117 خياراً، و53 مصدراً سريرياً ومهنياً. يغيّر التنويع المعلومات والبيئة المعروضة فقط ولا يغيّر المؤشرات السريرية أو القرار الأكثر أماناً أو الدرجة.
- خطوات متتابعة تعرض تغير الحالة والعلامات الحيوية ثم تطلب أفضل قرار تمريضي.
- تغذية راجعة مباشرة توضح لماذا كان الاختيار آمناً أو ناقصاً أو متأخراً أو غير آمن.
- بنك من 47 سؤالاً تدريبياً أصلياً ثنائي اللغة: 15 لمسار دراسة التمريض السعودي المستقل، و15 لمسار دراسة الممرض المسجل الدولي المستقل، و17 لمسار التدريب التمريضي المحوسب المستقل. لكل سؤال أربعة خيارات ومبرر خاص بكل خيار ومصادر سريرية؛ لا يستخدم البنك بنوداً رسمية أو متذكّرة أو سرية ولا يتنبأ بالاختبار أو الترخيص أو الكفاءة.
- `useExamSession` يدير مجموعة الأسئلة والسؤال الحالي والاختيارات والقفل وعداداً تنازلياً بمعدل 90 ثانية لكل سؤال. يحفظ الموعد النهائي المطلق وترتيب الأسئلة في `localStorage`، لذلك لا يعيد تحديث الصفحة الوقت أو يبدل ترتيب الخيارات.
- تدريب موجّه ينشئ مجموعة ثابتة قبل البدء، ويزيد ظهور المجالات الأقل دقة فقط بعد عتبة أدلة معلنة، مع تفضيل أسئلة لم تُجب بعد. وبعد كل مجموعة تستطيع `analyzePerformance(userAnswers, questionBank)` إنشاء متابعة من 10 أسئلة تركز على المجالات الأقل نتيجة.
- درجة للمحاولة، وعدد السيناريوهات المكتملة، وتحليل تعليمي لدقة هذه العينة ومجالات المراجعة، إضافة إلى ملخص لمجموعات الأسئلة المكتملة وترتيب مقترح للسيناريوهات. يعمل ذلك محلياً للضيف، وتتزامن سجلات الإنجاز الدنيا مع حساب خاص عند تسجيل الدخول.
- تمرين داخل سيناريو العناية الحرجة لترتيب ثلاث فرضيات تعليمية معروضة، مع تفسير ودرجة؛ لا يطلب من المتعلم صياغة تشخيص ولا يقدم تشخيصاً مؤكداً.
- صفحة مراجع تعرض 53 مصدراً سريرياً ومهنياً مع السنة وملاحظات الوصول والترخيص؛ لا تعرض مخططات مالكي الاختبارات كمصادر للأسئلة.
- الاشتراكات والأسعار والدفع والاستحقاقات خارج نطاق هذه المرحلة ولا تظهر في واجهة الموقع.
- تذييل مرئي يحمل الاسم بالضبط `Abdulkarim alhejaili`.

السيناريوهات الخيالية هي محتوى تعليمي ثابت ومراجع داخل المستودع؛ لا توجد سجلات مرضى تجريبية تُزرع وقت التشغيل، ولا اعتراض لطلبات المتصفح، ولا موفر سريري خارجي مزيّف.

«فرضيات تمريضية» مورد تعليمي مستقل لا يصدر عن أي جهة تنظيمية تمريضية أو مالك اختبار أو مزود تقديم اختبارات، ولا ترعاه أو تؤيده أو تعتمده أو تديره أيٌّ منها. لا يستخدم أسئلة متذكّرة أو سرية. كل المحتوى الحالي مسودة بانتظار مراجعة سريرية وقانونية ولغوية بشرية موثقة.

## خريطة الموقع | Routes

يستخدم الموقع مسارات `hash` حتى تعمل الحزمة الثابتة بلا اعتماد على إعادة كتابة مسارات من الخادم.

| المسار | الغرض |
| --- | --- |
| `#/home` | تعريف سريع، متابعة التعلم، والانتقال إلى السيناريوهات |
| `#/scenarios` | تصفح الحالات وترشيحها حسب القسم والصعوبة |
| `#/scenario/:id` | تنفيذ الحالة خطوة بخطوة، ثم المراجعة والتفسير |
| `#/result/:id` | debrief ونتيجة آخر محاولة مكتملة للحالة |
| `#/questions` | إعداد مجموعة مؤقتة من أحد مسارات الدراسة المستقلة الثلاثة، استعادتها بعد تحديث الصفحة، ثم مراجعة المبررات والمصادر وبدء متابعة مركزة |
| `#/learning` | ملخص المحاولات والدرجات ومؤشرات التعلم، ولوحة إنشاء الحساب أو تسجيل الدخول والمزامنة الاختيارية |
| `#/resources` | سجل المراجع الرسمية وملاحظات الترخيص |
| `#/about` | الغرض التعليمي، حدود الاستخدام، وسياسة المحتوى |
| `#/privacy` | إشعار التخزين المحلي والحساب الاختياري والمزامنة والاستضافة والروابط الخارجية |
| `#/terms` | شروط التعلم والاستخدام المقبول والحدود السريرية |
| `#/contact` | بريد المشروع وإرشادات بلاغات المحتوى والسلامة والحقوق |

أي مسار غير معروف يجب أن يعيد المستخدم بأمان إلى الصفحة الرئيسة. إنشاء الحساب وتسجيل الدخول بالبريد وكلمة المرور موجودان داخل `#/learning`، وليسا مسارين مستقلين.

## حساب التعلم والتخزين | Learning account and storage

يستطيع المستخدم المتابعة كضيف على الجهاز، أو إنشاء حساب Supabase اختياري بالبريد الإلكتروني وكلمة المرور لمزامنة سجل الإنجاز الأدنى بين أجهزته:

- يحفظ المتصفح نسخة محلية من اللغة ومحاولات السيناريوهات ومجموعات الأسئلة وجلسة الاختبار النشطة. تُربط الذاكرة المحلية بمالك الحساب الحالي لمنع ظهور تقدّم مستخدم سابق بعد تبديل الحساب على جهاز مشترك.
- وضع الضيف لا يحتاج بريداً أو حساباً؛ بياناته تخص المتصفح والأصل الحالي، ومسح بيانات الموقع يفقدها.
- عند تسجيل الدخول، تتزامن بصورة خاصة معرّفات المحاولات المكتملة ومعرّفات النشاط والخيارات المحددة وطوابع الإكمال. لا تُزامن جلسة الاختبار النشطة أو عدادها؛ تبقى محلية ومقيّدة بالمستخدم على الجهاز.
- يعاد حساب الدرجات وإشارات التعلم في المتصفح من بنك المحتوى المؤلف الحالي بدلاً من التعامل مع درجة مخزنة كحقيقة موثوقة أو شهادة كفاءة.
- يستخدم المخطط سياسات Row Level Security وعمليات RPC مرتبطة بهوية الجلسة؛ لا يستطيع المتصفح تحديد `user_id` لمستخدم آخر عند مزامنة سجل التعلم. هذا عزل لحسابات تعلم شخصية، وليس نموذج تعدد جهات مؤسسي مكتمل.
- يمكن لصاحب الحساب حذف سجلات التعلم المكتملة من الجهاز والحساب، مع الإبقاء على اللغة وجلسات التدريب النشطة. الحذف متزامن بحيث لا تعيد مزامنة قديمة السجلات المحذوفة.
- البريد الإلكتروني هو معرّف الحساب، وقد تتطلب البيئة تأكيده. لا تطلب الواجهة اسم مريض أو إجابة سريرية نصية حرة.
- لا ينبغي إدخال اسم مريض أو رقم ملف أو أي معلومات صحية أو تعريفية.
- يعيد محرك التعلم بناء الملخصات من حقول مسموح بها ويهمل الحقول غير المتوقعة، لكن `localStorage` ليس مخزناً آمناً للبيانات الحساسة.
- إعادة السيناريو تضيف محاولة جديدة؛ عدد الإنجاز يحسب السيناريوهات المكتملة الفريدة، لا عدد المحاولات.
- تحليلات الأسئلة محلية وتكوينية أيضاً. لا يظهر مؤشر فئة قبل الإجابة عن ثلاثة أسئلة فريدة على الأقل عبر مجموعتين مكتملتين، ولا ينشئ تكرار السؤال دليلاً إضافياً.
- يعتمد العداد على موعد نهائي مطلق، لا على قيمة تنقص فقط أثناء فتح الصفحة؛ لذلك يحسب الوقت المنقضي أثناء تحديث الصفحة أو إغلاق التبويب. عند انتهاء الوقت تُرسل المجموعة وتحتسب الأسئلة غير المجابة كإجابات غير صحيحة.

الحساب والمزامنة الحالية مناسبان لنسخة خاصة تجريبية فقط. استعادة كلمة المرور موجودة في الواجهة، لكن قبل النشر العام يجب اعتماد إعداد البريد والحماية من الإساءة وسياسات الخصوصية والاحتفاظ، وتنفيذ اختبار يدوي كامل لإنشاء الحساب وتأكيد البريد وتسجيل الدخول والاستعادة والمزامنة والحذف على بيئة النشر.

## الدرجات | Scoring

الدرجة تكوينية للتعلم فقط:

- لكل قرار قيمة من `0` إلى `100` وتصنيف: `safe` أو `gap` أو `delay` أو `unsafe`.
- درجة المحاولة هي متوسط القرارات المجاب عنها؛ إن بقيت خطوة بلا جواب فالنطاق `incomplete` وتعد المحاولة غير مكتملة.
- وجود قرار `unsafe` يفرض نطاق «مراجعة سلامة» حتى لو كان المتوسط مرتفعاً.
- لا تدخل المحاولات الجزئية في تحليل المهارات. ولا يعلن الموقع «نقطة ضعف» في أحد المجالات السبعة المشتركة حتى تتوفر ثلاثة قرارات مكتملة على الأقل عبر سيناريوهين مختلفين؛ وما قبل ذلك يظهر «بيانات غير كافية».
- التدريب الموجّه اقتراح تعليمي يبني مجموعة ثابتة قبل البدء؛ ليس اختباراً تكيفياً محوسباً ولا يقدّر القدرة أو احتمال النجاح أو الجاهزية.
- لا توجد درجة نجاح/رسوب، شهادة، ساعات تعليم مستمر، أو ادعاء صلاحية للعمل السريري.

التفصيل الكامل ومعايير التوسع موثق في [خارطة المنتج](docs/PRODUCT_BLUEPRINT.md).

## جولة عرض قصيرة | Showcase walkthrough

1. افتح `#/home` وبدّل بين العربية والإنجليزية للتأكد من RTL/LTR.
2. انتقل إلى `#/scenarios` واختر حالة من قسم مختلف.
3. أجب عن جميع الخطوات، وراجع التفسير والمصدر المرتبط بكل قرار.
4. افتح `#/questions`، وجرّب مسار التدريب المحوسب، واختر إجابة ثم حدّث الصفحة للتأكد من استعادة السؤال والاختيار والوقت المتبقي.
5. أكمل المجموعة، وراجع المبررات والمصادر، ثم ابدأ متابعة الـ10 أسئلة المركزة.
6. افتح `#/learning` لمشاهدة الملخص وحالة كفاية الأدلة. ويمكن اختيارياً إنشاء حساب وتأكيد البريد ثم تسجيل الدخول لاختبار مزامنة المحاولات المكتملة بين جلستين.
7. افتح سيناريو العناية الحرجة وتأكد من ظهور تمرين ترتيب الفرضيات وتفسير النتيجة.
8. افتح `#/resources` وتأكد من ظهور المصادر السريرية المباشرة، ثم راجع `#/privacy` و`#/terms` و`#/contact`.
9. تحقق من التذييل `Abdulkarim alhejaili`، ثم أعد الجولة بالعربية والإنجليزية عند عرض `390px` ولوحة المفاتيح فقط.

## ما يمنع عرضاً محلياً وما يمنع الإنتاج

### Showcase blockers — موانع العرض المحلي

هذه البنود تمنع تسليم النسخة للعرض إن لم تُتحقق فعلياً:

- فشل `pnpm install --frozen-lockfile` أو `pnpm test` أو `pnpm build` أو `pnpm test:sites`.
- غياب ملفات ناتج Sites الثلاثة المتوقعة بعد البناء.
- خطأ JavaScript ظاهر، مسار لا يفتح، أو فقد التقدم أثناء التنقل في المتصفح نفسه.
- تعطل تبديل اللغة، عكس غير صحيح للاتجاه، تمرير أفقي عند `390px`، أو مسار لا يعمل بلوحة المفاتيح.
- سيناريو أو سؤال بلا تفسير أو بلا مرجع، رابط رسمي/مخطط اختبار معطل، أو نص قد يُفهم كأمر رعاية حقيقي أو كسؤال اختبار رسمي.
- وجود تجاوز تجريبي للمصادقة، بيانات مريض، طلب شبكة سريري غير معتمد، أو اعتراض لطلبات المتصفح.

### Production blockers — موانع الإنتاج

نجاح العرض المحلي لا يثبت الجاهزية للإنتاج. قبل خدمة مستخدمين حقيقيين يلزم على الأقل:

- اعتماد سريري وقانوني ولغوي عربي موثق لكل سيناريو وسؤال وترجمة، وتنفيذ دورة المراجعة والسحب في [حوكمة المحتوى](docs/CONTENT_GOVERNANCE.md).
- حسم أصالة المحتوى وتراخيص إعادة الاستخدام وأذونات العلامات أو الرسومات أو الخوارزميات؛ الربط بالمصدر لا يمنح حق النسخ.
- تعيين ناشر مسؤول وقناة تواصل قانونية، واعتماد سياسة خصوصية وشروط استخدام سعودية ومراجعة PDPL والإقامة والاحتفاظ والحذف، مع منع بيانات المرضى وخطة استجابة للحوادث وطلبات أصحاب البيانات.
- إعداد SMTP مخصص وتأكيد البريد والاستعادة وCAPTCHA وحدود المعدل والمراقبة قبل فتح التسجيل للعامة؛ البريد الافتراضي في Supabase لا يكفي لخدمة عامة.
- إذا خُدمت جهات أو منشآت: نموذج تعدد جهات وتفويض مؤسسي وعزل على الخادم وسجل تدقيق وإدارة حسابات؛ حساب التعلم الشخصي الحالي لا يوفر ذلك.
- الاشتراكات والدفع والتجارة الإلكترونية ليست جزءاً من المنتج الحالي؛ أي قرار مستقبلي بإضافتها يحتاج مشروعاً مستقلاً ومراجعة جديدة ولا تعتمد عليه هذه البنية.
- بنية إنتاج معتمدة تفشل بإغلاق آمن؛ لا تُمكّن تحليلات أو بريد أو ذكاء اصطناعي أو تخزين خارجي قبل اعتماد المزود والمنطقة والاحتفاظ والعقود والأسرار ودليل التشغيل.
- مراجعة WCAG واختبارات أجهزة ومتصفحات فعلية بالعربية والإنجليزية، واختبار أمني خارجي مصرح به، ورؤوس أمنية وسياسة محتوى ومراقبة واعتمادية ونسخ احتياطي وتعافي.
- تحليل عدالة وصلاحية تعليمية للدرجات؛ وأي ادعاء شهادة أو كفاءة أو ساعات معتمدة يحتاج جهة اعتماد مستقلة ولا توفره هذه النسخة.
- تعيين مالك تشغيل ومالك محتوى، قناة بلاغ عاجل، اتفاق مستوى خدمة لتصحيح المحتوى، وآلية سحب فوري للسيناريو الخطر.

## إعداد المشغل | Operator setup

يعمل وضع الضيف المحلي بلا قاعدة بيانات. لتفعيل الحساب والمزامنة محلياً، أنشئ `.env.local` ولا تلتزم به في Git، وضع قيم البيئة العامة فقط:

```dotenv
VITE_SUPABASE_URL=
VITE_SUPABASE_PUBLISHABLE_KEY=
```

هذه قيم عميل عامة مقصودة للاستخدام في المتصفح وليست مفاتيح إدارية؛ تبقى الحماية مع RLS وعمليات RPC. لا تضع `service_role` أو SMTP أو أي سر إداري في متغير يبدأ بـ`VITE_`. قبل أي نشر عام على المشغل أن:

1. يشغل الفحوص أعلاه ويسجل النتائج والتاريخ والبيئة.
2. يؤكد أن البناء لا يحتوي أسراراً أو بيانات مرضى أو مداخل تجريبية مخفية.
3. يتحقق من العربية والإنجليزية على سطح المكتب وعرض `390px` ومن لوحة المفاتيح وعلى أجهزة ومتصفحات فعلية.
4. يراجع الروابط وحالة كل مصدر وتاريخ مراجعته والمطابقة على مستوى الادعاء، ويؤكد نص الاستقلال وعدم التنبؤ.
5. يختبر وضع الضيف، وعزل الذاكرة عند تبديل الحساب، وإنشاء الحساب وتأكيد البريد والدخول والخروج واستعادة كلمة المرور والمزامنة والتصدير والحذف من طرف إلى طرف قبل فتح التسجيل للعامة.
6. يؤكد عدم وجود مسار عضوية أو سعر أو شراء أو دفع في الواجهة الحالية.
7. يتحقق من ظهور الاسم `Abdulkarim alhejaili` بالضبط في التذييل.
8. يحدد إن كانت البيئة «عرضاً تعليمياً» أم «إنتاجاً»؛ لا يجوز وصف رفع حزمة ثابتة بأنه إطلاق إنتاجي.
