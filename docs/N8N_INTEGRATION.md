# حدود تكامل n8n | n8n Integration Boundary

**الحالة الحالية:** تصميم تشغيلي مستقبلي فقط. لا يتصل نموذج الموقع الحالي بـn8n، ولا يحتاج مفتاح n8n أو webhook للتشغيل المحلي.

## الدور الصحيح

n8n طبقة أتمتة وتكامل خلفية لتنفيذ workflows محددة بعد اعتمادها. ليس:

- واجهة الويب؛ تبقى واجهة React المستجيبة هي تجربة المتعلم.
- API المنتج أو قاعدة بياناته أو مخزن المحتوى.
- مزود هوية أو جلسة أو وسيلة لاستعادة الحساب.
- نظام استحقاق أو مصدر حقيقة للعضوية أو الاشتراك أو الدفع.
- قناة لإرسال بيانات مريض أو وثائق أو نصوص سريرية حرة.

لا توجد حالياً مصادقة أو قاعدة بيانات أو مدفوعات أو اشتراكات خادمية. عند بناء هذه الأنظمة لاحقاً، يقرر خادم المنتج الاستحقاق في كل طلب ويحتفظ بسجل الحالة الموثوق؛ لا تمنح نتيجة workflow أو قيمة في `localStorage` حق الوصول.

## البنية المقترحة

```text
Responsive web browser
  -> authenticated product API
  -> transactional outbox / durable event queue
  -> signed n8n webhook
  -> approved destination (email, ticketing, monitoring)

n8n callback, when required
  -> signed server-to-server endpoint
  -> schema and authorization validation
  -> idempotent product service command
  -> authoritative database and audit record
```

لا يستدعي المتصفح webhook خاصاً بـn8n مباشرة. لا يرسل الخادم حدثاً قبل تثبيت تغيير المجال في معاملة موثوقة؛ ويمنع transactional outbox فقد الحدث بين حفظ التغيير وإرساله.

## حمولة دنيا بلا بيانات مرضى

تستخدم قائمة سماح صريحة لكل نوع حدث. مثال لإشعار قرب موعد مراجعة محتوى:

```json
{
  "eventId": "evt_01J...",
  "eventType": "content.review_due",
  "occurredAt": "2026-09-04T10:00:00Z",
  "contentId": "oncology-neutropenic-fever",
  "contentVersion": "1.0.0",
  "reviewDueAt": "2026-12-04T00:00:00Z",
  "locale": "en",
  "correlationId": "corr_01J..."
}
```

الحمولة لا تحتوي اسم متعلم أو بريدَه أو رقم موظف، ولا معلومات مريض، ولا إجابة حرة، ولا إجابات اختبار، ولا درجات فردية، ولا tokens أو presigned URLs أو أسرار. إذا احتاج workflow مستقبلياً التواصل مع شخص، يرسل الخادم معرف إشعار داخلياً قصير العمر، وتسترجع خدمة مخولة الحد الأدنى اللازم؛ لا ينسخ n8n ملف المستخدم الكامل.

## توقيع webhooks ومنع الإعادة

- يستخدم TLS، ويوقع المرسل `HMAC-SHA256` على البايتات الخام للطلب بصيغة `timestamp + "." + rawBody`.
- ترسل رؤوس مثل `X-NH-Event-Id` و`X-NH-Timestamp` و`X-NH-Signature: v1=<hex>`؛ لا يوضع السر في URL أو الحمولة.
- يتحقق المستقبل من التوقيع بمقارنة ثابتة الزمن، ثم يرفض timestamp خارج نافذة قصيرة مقترحة قدرها خمس دقائق.
- يرفض أي `eventId` سبق قبوله ما لم تكن إعادة آمنة لنفس العملية؛ التوقيع وحده لا يمنع replay.
- توقع callbacks من n8n إلى خادم المنتج بسر مستقل واتجاه مستقل. تدعم عملية التدوير سراً حالياً وآخر تالياً لمدة انتقال محدودة.
- يمكن إضافة mTLS أو allowlist للشبكة عندما تسمح بيئة الاستضافة، لكنهما لا يحلان محل توقيع الرسالة والتحقق من المخطط.

## Idempotency والتناسق

- يكون `eventId`/`idempotencyKey` فريداً ومستقراً لكل تغيير مجال، ويحفظه المستلم في مخزن دائم بقيد uniqueness.
- يعيد الاستلام المكرر نتيجة العملية الأولى ولا يعيد إرسال بريد أو إنشاء تذكرة أو تنفيذ انتقال حالة.
- تستخدم كل خطوة خارجية مفتاح idempotency مشتقاً من الحدث والخطوة، مثل `eventId:notify-reviewer`.
- يسجل الخادم إصدار المحتوى والحالة المتوقعة قبل قبول callback؛ أي callback قديم أو متعارض يرفض ولا يكتب فوق قرار أحدث.
- انتقالات النشر والسحب والاستحقاق لا تنفذ داخل n8n وحده. يطلب workflow أمراً من API، ويعيد API التحقق من الدور والحالة والمراجعات المطلوبة.

## إعادة المحاولة والفشل المغلق

- تعد استجابة `2xx` نجاحاً. تعاد المحاولة عند timeout و`429` وأخطاء `5xx` فقط، مع exponential backoff وjitter وحد أقصى موثق للمحاولات.
- لا تعاد تلقائياً طلبات فشلت بسبب توقيع أو مخطط أو صلاحية (`4xx`)، بل تنتقل إلى مراجعة تشغيلية.
- بعد استنفاد المحاولات ينتقل الحدث إلى dead-letter queue مع تنبيه وrunbook لإعادة تشغيله يدوياً بالمفتاح نفسه.
- يحدد workflow timeout لكل موصل، ولا يحتجز طلب المستخدم في المتصفح بانتظار سلسلة الأتمتة.
- فشل n8n لا ينشر محتوى، ولا يمنح عضوية، ولا يغير نتيجة تعلم، ولا يرسل رسالة بديلة غير مراجعة. تبقى الحالة الآمنة في خادم المنتج ويظهر للمشغل أن الإجراء الآلي معلق.

## التدقيق والمراقبة

يسجل كل طرف الحد الأدنى من metadata: `eventId`، نوع الحدث، correlation ID، إصدار workflow، وقت الاستلام والانتهاء، عدد المحاولات، النتيجة، فئة الوجهة، وهوية الخدمة/المشغل الذي أعاد التشغيل. لا تسجل الأسرار أو رؤوس التوقيع الكاملة أو bodies الحساسة.

تحدد سياسة الاحتفاظ مدة سجلات التنفيذ والـdead-letter، ومن يقرأها، وكيف تصدر أو تحذف. تنبه المراقبة عند ارتفاع فشل التوقيع، أو backlog، أو تكرار غير متوقع، أو تجاوز SLA، مع اختبار دوري للاستعادة وإعادة التشغيل الآمن.

## إدارة الأسرار

- تحفظ أسرار webhook وبيانات الموصل في n8n Credentials أو secret manager معتمد، وفي secret manager الخاص بخادم المنتج؛ لا تحفظ في Git أو ملفات الواجهة أو `localStorage` أو نص workflow قابل للتصدير.
- تستخدم حسابات خدمة بأقل صلاحية، وسراً مختلفاً لكل بيئة واتجاه وموصل، وتمنع بيئة الاختبار من الوصول إلى وجهات الإنتاج.
- توثق الملكية وتاريخ الإنشاء وآخر تدوير وموعد التدوير التالي وإجراء الإبطال الطارئ.
- تخفى القيم من logs ولقطات الدعم وexports، ويعامل تصدير workflow كعنصر حساس يراجع قبل المشاركة.

## Workflows مقترحة

1. **تذكير مراجعة المحتوى:** حدث `content.review_due` ينشئ مهمة للمراجع ويرسل تذكيراً بلا بيانات متعلم.
2. **مراقبة روابط المصادر:** جدول دوري يفحص URLs العامة للمراجع، ثم يفتح تذكرة عند تغير/تعطل الرابط؛ لا يقرر تلقائياً أن التوصية ما زالت صالحة.
3. **إشعار النشر أو السحب:** بعد أن يعتمد خادم المنتج انتقال الحالة، يوزع n8n إشعاراً للمالكين. لا ينشر n8n الحالة بنفسه.
4. **تنسيق بلاغ سلامة المحتوى:** يرسل معرف البلاغ ودرجة الأولوية والمالك فقط إلى نظام تذاكر معتمد؛ تحفظ التفاصيل الحساسة في النظام المصدر.
5. **تجميع دليل الإصدار:** يجمع روابط نتائج البناء والاختبارات والمراجعات ويخطر مسؤول الإصدار، من دون أسرار أو artifacts تحتوي بيانات.
6. **أحداث الاشتراك المستقبلية:** لا تبدأ إلا بعد وجود مزود دفع وAPI وقاعدة بيانات واستحقاقات خادمية. يمكن لـn8n تنسيق إشعار أو تذكرة، لكن webhook الدفع يدخل أولاً إلى endpoint خادمي موقّع ومختبر، ويظل الخادم مصدر الحقيقة.

## إعداد المشغل قبل التفعيل

- اعتماد مالك workflow، غرضه، مخطط الحدث، قائمة الحقول، الوجهات، المنطقة، DPA، والاحتفاظ.
- توفير n8n معزول حسب البيئة، TLS، نسخ احتياطي، مراقبة، dead-letter، وحسابات خدمة محدودة.
- إنشاء الأسرار في مخازنها المعتمدة وتوثيق التدوير والإبطال من دون نسخ القيم إلى المستودع.
- اختبار signature صالح/خاطئ، timestamp قديم، replay، duplicate delivery، timeout، `429`/`5xx`، فشل الوجهة، وإعادة التشغيل اليدوي.
- إثبات أن تعطل n8n لا يفتح وصولاً ولا ينشر محتوى ولا يعطل رحلة التعلم الأساسية.
- تسجيل runbook وSLA والتنبيه والمسؤول المناوب، ثم موافقة الأمن والخصوصية والتشغيل قبل تفعيل أول endpoint إنتاجي.

يبقى التكامل معطلاً افتراضياً حتى اكتمال هذه البوابة. نجاح الموقع المحلي أو بناء Sites لا يثبت جاهزية n8n أو أي خدمة إنتاجية.
